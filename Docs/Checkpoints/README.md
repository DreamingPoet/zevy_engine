# Codex 任务检查点

这里保存跨上下文、应用重启和对话切换仍可恢复的项目状态。

## 文件约定

- `CURRENT.md` 始终保存最新、完整、可继续执行的状态。
- 阶段完成后新增 `YYYY-MM-DD-<stage>.md` 历史快照。
- 阶段中途暂停时只更新 `CURRENT.md`，不制造大量无价值快照。
- 新对话或上下文压缩后，先读根 `AGENTS.md`，再读 `CURRENT.md`。

## 状态证据优先级

1. 实际文件、Git 状态和刚执行的测试；
2. `CURRENT.md`；
3. 历史阶段快照；
4. 压缩后的聊天摘要或记忆。

检查点必须写清楚哪些结论来自代码、PC 测试、Android/VR 实测、用户观察或尚未验证的设计。禁止把计划、推测或旧测试写成当前已验证结果。

## 阶段检查点模板

```markdown
# 任务检查点：<阶段名称>

## 元数据

- 更新时间：YYYY-MM-DD HH:MM，Asia/Shanghai
- 状态：进行中 / 已完成 / 阻塞
- 工作区：绝对路径
- 分支与 HEAD：branch @ commit
- 下一恢复入口：本文件

## 最终目标和完成标准

- 最终目标：
- 产品完成标准：
- 当前阶段完成标准：

## 已完成内容

- [实现/PC/Android-VR/设计] 内容与证据

## 当前文件和修改状态

- `git status --short` 摘要
- 本阶段修改文件与用途
- 既有/用户改动及保护要求

## 关键决定与禁止事项

- 已决定：
- 产品不变量：
- 禁止：

## 测试结果

- 已执行：命令、设备、结果
- 未执行：项目及原因
- 用户实测：观察与限制

## 未完成步骤和下一步

1. 未完成步骤
2. 风险/依赖
3. 唯一明确的下一步

## 恢复时首先读取

- `AGENTS.md`
- 本检查点关联的规格、代码和测试文件
```

## 更新检查表

- 是否先检查了实际 `git status`、分支和 HEAD？
- 是否把每项内容标成实现、设计或哪类测试证据？
- 是否列出未提交、已暂存和不应覆盖的用户改动？
- 是否保留了最终目标、完成标准和禁止事项？
- 是否只写实际运行过的测试？
- 下一步是否具体到可以直接开始，而不是“继续优化”？
